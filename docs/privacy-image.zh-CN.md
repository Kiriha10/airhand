# Windows 被控端图片隐私屏

本功能基于上游 `b4e75fb`，同时保留本地 `3287057` 及之前的游戏点击、触控板和色彩修复。源码分支为 `codex/privacy-image`。本轮只增加 Windows 图片遮罩，不扩展 macOS / Linux。

图片由被控端用户在托盘菜单导入，控制端只能使用上游已有的防窥开关，不接收图片、图片路径或图片下载地址。勾选本机“连接时自动遮挡”后，通过配对且确认了握手的会话会自动开启遮罩；未确认的握手不能触发。

## 方案评价

| 项目 | 上游驱动黑屏 | 本分支图片遮罩 |
| --- | --- | --- |
| 物理显示器 | 撤出桌面、没有信号 | 保持工作、显示纯黑或本机图片 |
| 需要 MttVDD | 是，且要允许启用设备 | 不需要 |
| Windows 要求 | 依上游驱动与安装要求 | Windows 10 2004 / build 19041 起 |
| 远控画面 | 切换到虚拟显示器 | 保持原显示器与桌面布局 |
| 自定义图片 | 无 | 被控端本机导入 PNG/JPEG |
| UAC / 锁屏 / 独占全屏 | 由上游驱动隔离处理 | 不能承诺覆盖，安全桌面时报告失败 |
| 本机恢复 | 依上游退出、断线恢复流程 | 同上，另有本机 Ctrl+Alt+Shift+F12 |

这个方案适合“电脑前显示指定图片，远程继续操作”的需求，也避免安装显示驱动和改显示拓扑。它是视觉遮挡，能力边界比驱动隔离窄。物理屏幕既要显示图片，就不能同时把该显示器撤成无信号；因此两种模式互斥，由被控端选择。

## 实现

复用上游 `ControllerMsg::Privacy`、`PrivacyState`、会话租约以及 `ending` 的断开/重连/锁屏流程。图片不进入远控协议；Android/iOS 不增加选图或图片存储逻辑。驱动模式默认保持上游行为，图片模式和自动开启均由本机托盘配置。

Windows 原生窗口每个显示器一份，无边框、不激活、不取得焦点，覆盖显示器的完整物理像素范围，图片按比例居中，剩余部分为不透明黑色。创建后先设置并检查 `WDA_EXCLUDEFROMCAPTURE`，成功后才显示。显示器变化时先创建新遮罩，再撤旧遮罩。进程结束时 Windows 销毁窗口。全局隐藏系统光标会影响现有游戏/拖动识别，因此本功能不修改光标可见性；物理屏幕上仍可能看到系统指针。

复用上游本机输入拦截，只允许带 Airhand 标记的远程注入和释放事件；为图片模式补充本机 Ctrl+Alt+Shift+F12 恢复。该组合不接受远程注入模拟。正常断开按上游流程结束，断线保留遮挡等待重连，最后一个会话结束按原“结束远程后锁屏”设置先锁屏。设置改动在所有会话离开后执行，避免驱动和图片模式切换到一半。

## 图片与写入位置

- 源文件上限 8 MiB，解码像素总量上限 1600 万，只接受静态 PNG/JPEG。
- 解码前检查图片尺寸；导入后将透明像素叠到黑底，长边缩小到不超过 2560 像素，规范化为 JPEG。
- 托盘以登录用户身份读取选择的源文件；系统服务接收经验证的内容，并再次验证，不以 SYSTEM 身份打开任意来源路径。
- 导入副本固定为被控端配置文件旁的 `privacy-image.jpg`，写入时先用 `privacy-image.jpg.tmp`。配置仍由既有的原子写入机制更新。
- `config.toml` 新增 `privacy_screen = "driver" | "image"`、`privacy_auto`、`privacy_custom_image`。删掉配置文件后重建时保留这三项。
- 本地托盘与服务通过已有的同用户会话命名管道交互；远程网络协议不包含图片。

## 验证要求

需要同时验证本机遮罩可见、DXGI 看到后面的实时画面、撤掉遮罩后窗口销毁，而不是仅检查 API 返回成功。另需覆盖图片导入失败、透明图、图片尺寸上限、多显示器、连接确认、多人会话、正常断开、断线重连、本机恢复、进程退出以及原拖动松键回归。

单显示器实测不等于多显示器/HDR/各种显卡/安全桌面均已验证。具体通过项目以产物的构建信息和测试日志为准。

2026-11-24 在本机完成：桌面单元测试 115 项通过；另外显式执行 2 项真实窗口集成测试，验证 DXGI 排除遮罩且后方画面继续更新、多会话最后释放后恢复、隐藏遮罩后下一轮重新显示、测试窗口全部销毁。协议和链路共 210 项通过，前端 113 项通过，Android 164 项通过（含保留的 44 项手势测试）。其余需要特定硬件或外设的桌面忽略项未执行。未在多显示器、HDR 或独占全屏游戏下实测，未安装到当前正在使用的 Airhand。
