# Windows 被控端图片隐私屏

本功能已合入上游 `246e686`，同时保留本地 `3287057` 及之前的游戏点击、触控板和色彩修复，以及后续安卓菜单系统栏修复。源码分支为 `codex/privacy-image`。图片遮罩只支持 Windows，不扩展 macOS / Linux。

图片由被控端用户在托盘菜单导入，控制端只能使用上游已有的防窥开关，不接收图片、图片路径或图片下载地址。勾选本机“连接时自动遮挡”后，通过配对且确认了握手的会话会自动开启遮罩；未确认的握手不能触发。

## 方案评价

| 项目 | 上游驱动黑屏 | 本分支图片遮罩 |
| --- | --- | --- |
| 物理显示器 | 撤出桌面、没有信号 | 保持工作、显示纯黑或本机图片 |
| 需要 MttVDD | 是，且要允许启用设备 | 不需要 |
| Windows 要求 | 依上游驱动与安装要求 | Windows 10 2004 / build 19041 起；为所有用户安装、服务提供 UIAccess |
| 远控画面 | 切换到虚拟显示器 | 保持原显示器与桌面布局 |
| 自定义图片 | 无 | 被控端本机导入 PNG/JPEG |
| UAC / 锁屏 | 由上游驱动隔离处理 | Default 和 Winlogon 各自预置遮罩，切换保留防窥请求；实际验证结果见下文 |
| 独占全屏 | 由上游驱动隔离处理 | 窗口遮挡无法保证，需要驱动模式 |
| 本机恢复 | 依上游退出、断线恢复流程 | 同上，另有本机 Ctrl+Alt+Shift+F12 |

这个方案适合“电脑前显示指定图片，远程继续操作”的需求，也避免安装显示驱动和改显示拓扑。它是视觉遮挡，能力边界比驱动隔离窄。物理屏幕既要显示图片，就不能同时把该显示器撤成无信号；因此两种模式互斥，由被控端选择。

## 实现

复用上游 `ControllerMsg::Privacy`、`PrivacyState`、会话租约以及 `ending` 的断开/重连/锁屏流程。图片不进入远控协议；Android/iOS 不增加选图或图片存储逻辑。驱动模式默认保持上游行为，图片模式和自动开启均由本机托盘配置。

Windows 原生窗口每个显示器一份，无边框、不激活、不取得焦点，覆盖显示器的完整物理像素范围，图片按比例居中，剩余部分为不透明黑色。显示前设置 `DWMWA_EXCLUDED_FROM_PEEK`、`DWMWA_DISALLOW_PEEK`，阻止系统窗口预览把遮罩渐隐；设置并检查 `WDA_EXCLUDEFROMCAPTURE`，成功后才显示。这两个 DWM Peek 属性只支持设置，不能用 `DwmGetWindowAttribute` 读回。显示器变化时先创建新遮罩，再撤旧遮罩。窗口事件触发层级维护，并保留周期检查处理显示器变化和系统隐藏操作。

服务只给自己复制出的被控端主令牌设置 `TokenUIAccess`，不修改托盘令牌或 UAC 系统策略。图片模式在缺少 UIAccess 时不可用，原驱动模式和远控继续按原权限工作。

合入上游后，图片模式也复用本机输入提前结束断线等待的逻辑：防窥期间本机有人按键、点击或滚动，失联的控制端不再等待重连，按既有设置先锁屏再撤罩；仍在线的控制端不因此被断开。保留图片模式的本机紧急恢复组合键。图片模式不参与驱动补屏的显示器跟随，避免上游新增的补屏切换逻辑将它误当作驱动模式。

开启时，管理器先在 Winlogon、再在 Default 各启动独立线程，在目标桌面创建遮罩并准备物理光标保护；全部准备成功后才报告开启。UAC 不再使普通桌面遮罩销毁或清除防窥请求。每个线程在销毁自己的窗口和钩子后恢复原桌面并关闭句柄，不把已有 HWND 直接搬到另一个桌面。

物理光标使用 `Magnification.dll` 的 `MagShowSystemCursor(FALSE)` 隐藏，退出时恢复；不调用 `ShowCursor` 改变显示计数。原生像素检查发现：隐藏后 `GetCursorInfo` 仍显示逻辑光标存在，而 DXGI 原始画面没有光标，旧分类会误报 `InFrame`。因此隐私屏期间读取 Win32 逻辑可见性、位置和光标位图，为远端继续发送 `Shown/Hidden` 与形状，并为要求带光标的画面重新绘制光标。游戏自己隐藏光标时保留 `Hidden`；未开启图片遮罩时沿用原 DXGI 路径。

复用上游本机输入拦截，只允许带 Airhand 标记的远程注入和释放事件；为图片模式补充本机 Ctrl+Alt+Shift+F12 恢复。该组合不接受远程注入模拟。正常断开按上游流程结束，断线保留遮挡等待重连，最后一个会话结束按原“结束远程后锁屏”设置先锁屏。设置改动在所有会话离开后执行，避免驱动和图片模式切换到一半。

## 图片与写入位置

- 源文件上限 8 MiB，解码像素总量上限 1600 万，只接受静态 PNG/JPEG。
- 解码前检查图片尺寸；导入后将透明像素叠到黑底，长边缩小到不超过 2560 像素，规范化为 JPEG。
- 托盘以登录用户身份读取选择的源文件；系统服务接收经验证的内容，并再次验证，不以 SYSTEM 身份打开任意来源路径。
- 导入副本固定为被控端配置文件旁的 `privacy-image.jpg`，写入时先用 `privacy-image.jpg.tmp`。配置仍由既有的原子写入机制更新。
- `config.toml` 新增 `privacy_screen = "driver" | "image"`、`privacy_auto`、`privacy_custom_image`。删掉配置文件后重建时保留这三项。
- 本地托盘与服务通过已有的同用户会话命名管道交互；远程网络协议不包含图片。

## 验证要求

需要同时验证本机遮罩可见、DXGI 看到后面的实时画面、撤掉遮罩后窗口销毁，而不是仅检查 API 返回成功。另需覆盖图片导入失败、透明图、图片尺寸上限、多显示器、连接确认、多人会话、正常断开、断线重连、本机恢复、进程退出以及原拖动松键回归。

单显示器实测不等于多显示器/HDR/各种显卡/安全桌面均已验证。具体通过项目以产物的构建信息和测试日志为准。

首版 `af2a96b` 在 2026-11-24 完成：桌面单元测试 115 项通过，另外 2 项真实窗口测试通过；协议和链路 210 项、前端 113 项、Android 164 项通过（含保留的 44 项手势测试）。这些结果属于首版基础遮罩，不代表当时已验证 Peek、实际文件夹拖拽或真实 UAC。

本次针对物理屏幕漏出的修复已通过 116 项桌面测试，包括箭头、文本和十字系统光标的实际位图转换；原生像素测试确认物理光标隐藏后原始画面没有光标、远端状态为 Shown，带光标画面仍有实际光标像素。普通桌面原生遮罩测试也已通过，实际 DXGI 排除遮罩且后方画面继续更新，撤罩后测试窗口销毁。

跨 Winlogon 的原生验证需要管理员权限。当前 Windows 提权启动请求返回“操作已被用户取消”，临时测试服务未创建，相关测试尚未执行。因此本次产物标为候选包，不能把 UAC 保持、UIAccess 窗口 band 和 Winlogon 捕获排除视作已实测通过。验证工具与结果日志位于工作区 `.build-cache/privacy-hardening`。多显示器、HDR、独占全屏和手机会话也未完成本轮实测。

本轮也修正了上游 `airhand-link` 的一处陈旧测试初始化：它仍给 `QualitySettings` 设置已删除的 `transport` 字段，导致开启 console 特性的测试无法编译。
